## 二、根因（本地复刻锤死）

按 `morning-workflow.js` 的同一顺序本地复刻 P0-①，**首次调用就撞上**：

```
fuyao /api/a-share-index/constituents/ths-stock-list
  → code=429  Global request rate limit exceeded
```

旧代码链路（`logic/morning-workflow.js#fetchAndWriteWatchlist`）：

```js
const ladderRes = await settled(fetchLadderConstituents(env));          // ← 无任何重试
if (!ladderRes.ok) {
  logs.push('获取成分股失败: ' + ladderRes.e.message);
  return { error: '获取成分股失败: ' + ladderRes.e.message };           // ← runMorning 整轮 return
}
```

⇒ `runMorning` 拿到 `error` 直接返回 ⇒ **auction_watchlist / market_metrics / stock_range_pct 一张表都没写**
⇒ 第一页空白、无法操作。

**为什么是它**：`fetchLadderConstituents` 是 P0-① 的**第一个请求**，紧贴 9:25 出网，
正撞 fuyao 全局限流最紧的时刻；且本次实测该限流是**突发性**的
（同一接口相邻两次调用「一次 200、一次 429」，退避 1~2 秒即恢复）
⇒ **加重试即可解决**，而旧代码连一次重试都没有。
